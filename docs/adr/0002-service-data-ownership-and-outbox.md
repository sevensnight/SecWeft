# ADR-0002：服务独占数据写入并使用 Outbox/Inbox

- 状态：Accepted
- 日期：2026-07-10
- 决策范围：数据所有权、异步一致性和消息可靠性

## 背景

目标系统包含长任务、模型调用、知识索引、审批、Sandbox、证据和报告。若服务共享表或使用分布式事务，会产生强耦合、难以独立迁移和不可控故障。消息系统采用至少一次投递，重复和乱序是正常情况。

## 决策

1. 每个领域实体只有一个写入服务。
2. MVP 可共享 PostgreSQL 集群，但按服务使用独立 schema 和数据库账号。
3. 服务禁止查询其他服务 schema；跨服务使用 API、命令或事件。
4. 领域变更和 outbox 在一个本地事务提交。
5. Relay 可靠发布到 NATS JetStream；消费者用 inbox 的 `event_id` 唯一约束去重。
6. 事件携带 `aggregate_version`；旧版本忽略，版本缺口延迟并重放。
7. 大对象放对象存储，事件只携带 URI、hash 和安全元数据。
8. Redis/NATS 不作为 Task、Approval、Evidence 的唯一持久真相。

## 备选方案

### 所有服务共享表和 ORM

拒绝。无法明确所有权，迁移和权限边界失效。

### 两阶段提交/分布式事务

拒绝。运维复杂、可用性差，且多数流程本质为长事务和补偿工作流。

### 先写数据库再直接发布消息

拒绝。进程在两步之间崩溃会永久丢事件。

### 只依赖消息系统保存业务状态

拒绝。MVP 不采用完整 event sourcing，查询、迁移和保留要求需要规范业务数据库。

## 结果

正面结果：本地事务清晰；服务可独立演进；消息故障可恢复；重复投递可测试。

负面结果：跨服务数据最终一致；需要 outbox relay、inbox、reconciliation 和投影版本管理。

## 约束

- Event Schema 必须版本化并执行兼容性检查。
- Consumer 的副作用必须与 inbox 处理原子提交，或使用独立幂等键。
- 删除、对象存储和索引同步需要补偿/DLQ/reconciliation。
- 禁止通过只读数据库账号绕过 API 获取其他领域数据。

## 验证

- 数据库权限测试证明服务账号不能访问其他 schema。
- 故障注入验证事务提交后 relay 可重发。
- 重复/乱序消息测试不产生重复 SandboxRun、Evidence 或 Report。
- 事件缺口有可观测指标、重放和人工处置流程。
