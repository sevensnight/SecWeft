# ADR-0001：采用演进式领域服务提取

- 状态：Accepted
- 日期：2026-07-10
- 决策范围：P0–P8 总体架构演进

## 背景

现有系统是单 FastAPI、SQLite 的可运行授权靶场原型，包含有价值的 Scope、审计、模型路由、上下文、RAG 和受限 Sandbox 安全算法。目标要求 Monorepo、清晰服务边界、多租户、可扩展部署和独立数据所有权。

直接继续扩展单体会固化跨模块表访问、进程内锁和四角色权限；一次性重写全部代码又会丢失已经验证的安全不变量，并造成长时间不可运行。

## 决策

采用演进式服务提取：

1. P0 先定义 bounded context、契约、数据所有权、状态机和安全门禁。
2. 现有测试保留为 characterization tests。
3. 每次只迁移一个领域；目标服务取得独立 API/事件、独立 schema 和写所有权后，旧入口停止该领域写入。
4. 允许部分服务在早期同进程部署，但只能通过公开接口组合，禁止跨模块内部表访问。
5. Sandbox worker 从一开始就是独立 Linux 信任区，不与 API 合并。
6. 兼容入口有明确退出阶段，不成为永久第二套架构。

## 备选方案

### 继续增强现有单体

拒绝。短期开发快，但无法满足数据所有权、独立扩缩容、Sandbox 信任区和多租户隔离要求。

### 一次性重写全部微服务

拒绝。迁移周期不可控，安全回归风险高，并违反每阶段可运行、可测试、可回滚的要求。

### 每个业务模块立即独立部署

拒绝。P0 阶段会引入大量网络、运维和一致性复杂度，却没有真实负载证据。

## 结果

正面结果：保留测试和安全算法；每次迁移可验证；部署拆分可随负载演进。

负面结果：过渡期存在兼容层和双形态代码；需要严格禁止双写真相和无限延长兼容期。

## 约束

- “文件移动”不等于领域完成迁移。
- 迁移完成必须满足独立契约、独立数据、无跨库读取、目标测试通过、旧写路径关闭。
- 新业务不得继续加入旧单体后再等待未来拆分。
- P0 不以空目录或固定成功端点假装服务已实现。

## 验证

- 能力矩阵为每个领域指定唯一目标服务。
- 架构测试检查服务依赖和跨 schema 权限。
- 每个阶段记录旧路径关闭证据和 characterization test 迁移结果。
